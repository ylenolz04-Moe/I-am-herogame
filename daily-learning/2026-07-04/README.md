# Day 7 — C# 装饰器模式 (Decorator Pattern)

> **日期:** 2026-07-04  
> **难度:** ★★★☆☆  
> **技术栈:** C# · Unity · 设计模式 · 装备系统 · Buff/Debuff · ScriptableObject

---

## 🎯 今日主题

装饰器模式动态地给对象添加额外的职责，像洋葱一样层层包裹。在游戏开发中，它是武器附魔、Buff/Debuff 叠加、技能修饰、伤害计算管道的核心模式。

---

## 📖 核心知识点

| # | 知识点 | 说明 |
|---|--------|------|
| 1 | IComponent 接口 | 装饰器和被装饰对象实现同一接口 — 对外透明 |
| 2 | ConcreteComponent | 基础武器（剑/弓/杖）— 装饰的起点 |
| 3 | BaseDecorator 抽象类 | IS-A + HAS-A — 既是武器又持有武器 |
| 4 | 火焰附魔 | 增加火焰伤害 + 灼烧 DoT 效果 |
| 5 | 冰霜附魔 | 冰霜伤害 + 减速 debuff |
| 6 | 毒液附魔 | 持续伤害 (Damage over Time) |
| 7 | 雷电附魔 | 连锁伤害 — 弹射至附近敌人 |
| 8 | 吸血附魔 | 生命偷取 — 造成伤害百分比回血 |
| 9 | 嵌套组合 | 火焰冰霜剑 / 剧毒雷电吸血弓 — 任意顺序叠加 |
| 10 | 组合爆炸 | 3种武器×5种附魔: 继承需93类 vs 装饰器只需8类 |
| 11 | Buff 装饰器 | 力量祝福 / 铁壁光环 / 疾风步 — 属性增益 |
| 12 | 双刃剑 Buff | 狂战士之怒 — ATK×1.5 但 DEF×0.6 HP×0.8 |
| 13 | Debuff 装饰器 | 虚弱诅咒 — 全面降低属性 |
| 14 | 叠层顺序 | 加法和乘法混合时，装饰器顺序影响最终结果 |
| 15 | ScriptableObject 集成 | 策划可在 Unity Editor 配置附魔数据 |
| 16 | 数据驱动装饰器 | GenericEnchant — 运行时根据 SO 数据创建 |
| 17 | 装饰器工厂 | EnchantFactory — 封装复杂创建 + 预置神器配方 |
| 18 | 伤害计算管道 | 装饰器链: 基础→元素→暴击→护甲→最终 |
| 19 | 装饰器 vs 继承 | 继承=编译时静态 / 装饰器=运行时动态可组合 |
| 20 | 开闭原则 | 新增附魔不改旧代码 — 新建装饰器类即可 |

## 🔗 与其他学习日的关系

- **Day 2 (对象池):** 装饰器实例可池化 — 高频附魔切换不产生 GC
- **Day 3 (事件系统):** 附魔触发时发布事件 → 播放特效/音效/UI飘字
- **Day 4 (状态机):** 不同状态可应用不同 Buff 装饰器组合
- **Day 5 (命令模式):** 命令封装操作 → 装饰器增强操作（装饰命令模式）
- **Day 6 (策略模式):** 策略替换算法 → 装饰器在原算法上叠加（互补关系）

---

## 💡 一句话总结

> 把对象像洋葱一样层层包裹 — 每一层增加新能力，而对象本身不知道（也不关心）自己被套了多少层。继承给你一把瑞士军刀，装饰器给你一套可以任意搭配的战术配件。

---

## 🧪 运行方式

将 `DecoratorPattern.cs` 放入 Unity 项目的任意 `Scripts` 文件夹中，在场景中创建空 GameObject 并挂载 `DecoratorDemo` 组件，运行后即可在 Console 中看到所有演示输出。
