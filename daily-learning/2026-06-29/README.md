# Day 6 — C# 策略模式 (Strategy Pattern)

> **日期:** 2026-06-29  
> **难度:** ★★★☆☆  
> **技术栈:** C# · Unity · 设计模式 · AI 系统 · 战斗系统

---

## 🎯 今日主题

策略模式定义了一系列算法，把它们一一封装起来，并使它们可以互相替换。在游戏开发中，它是 AI 行为系统、伤害计算、移动方式、技能系统的核心模式。

---

## 📖 核心知识点

| # | 知识点 | 说明 |
|---|--------|------|
| 1 | IStrategy 接口 | 策略模式的最小契约 — 所有策略实现同一接口 |
| 2 | 具体策略类 | AggressiveAI / DefensiveAI / PatrolAI / AmbushAI |
| 3 | Context 上下文 | 策略间共享的数据载体，策略只处理算法 |
| 4 | 运行时切换 | 同一套数据，不同的处理方式 → 动态改变行为 |
| 5 | 策略缓存 | 预创建策略实例避免 GC，配合对象池使用 |
| 6 | 伤害计算策略 | Physical / Magic / True / Percent — 不同公式封装 |
| 7 | 技能 = 策略 | Fireball / Heal / AOE → 技能栏 = 策略数组 |
| 8 | 策略 vs 状态 | 策略：外部决定怎么做 / 状态：内部自动切换 |
| 9 | 策略工厂 | 集中管理创建 → 运行时注册新策略 |
| 10 | OCP 开闭原则 | 新增策略不改旧代码，对扩展开放对修改关闭 |

---

## 💡 一句话总结

> 把"怎么做一件事"封装成可插拔的策略 — 同一个角色，换上不同的策略就变成完全不同的敌人；同一个技能栏，换上不同的策略就变成完全不同的职业。
