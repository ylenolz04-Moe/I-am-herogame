# Day 11 — C# 外观模式 (Facade Pattern)

> **日期:** 2026-07-18  
> **难度:** ★★☆☆☆  
> **技术栈:** C# · Unity · 设计模式 · GameManager · 子系统整合 · 战斗系统

---

## 🎯 今日主题

外观模式给复杂子系统提供一个简洁的入口。就像饭店前台服务员 — 你说"来一桌菜"，服务员帮你协调后厨、传菜、收银等一堆人。外观让你不需要知道内部有多复杂，一行调用搞定所有协调。

---

## 📖 核心知识点

| # | 知识点 | 说明 |
|---|--------|------|
| 1 | 外观模式核心 | 复杂子系统 A+B+C+D → Facade.一键操作() |
| 2 | GameFacade | 开始游戏 / 进入关卡 / 暂停 / 保存退出 — 一站式管理 |
| 3 | CombatFacade | 攻击 = 冷却检查 + 伤害计算 + 特效 + 音效 + UI — 一行搞定 |
| 4 | 子系统协调 | 外观按正确顺序调用子系统（先禁用输入→再黑屏→再加载→再恢复） |
| 5 | 暂停/恢复 | 统一控制输入、音量、UI、Time.timeScale |
| 6 | 多个外观 | 不同场景用不同外观，避免 God Object |
| 7 | 平台适配 | 同一外观，不同平台不同配置 |
| 8 | 外观 vs 适配器 vs 装饰器 | 外观简化、适配器转换、装饰器增强 — 三种"包装"的不同目的 |
| 9 | 外观 + 单例 | 常见组合：GameManager 既是外观又是单例 |

---

## 🔗 与其他学习日的关系

- **Day 10 (适配器):** 适配器转换接口，外观简化接口 — 目的不同但都是包装模式
- **Day 9 (工厂方法):** 工厂创建子系统对象 → 外观整合它们
- **Day 8 (模板方法):** 模板定义流程骨架 → 外观封装流程调用
- **Day 7 (装饰器):** 装饰器增强功能 → 外观不是增强，是简化
- **Day 5 (命令模式):** 外观的一个方法可以封装多个命令
- **Day 3 (事件系统):** 子系统间通过事件解耦 → 外观统一对外接口

---

## 💡 一句话总结

> 外观模式就是给复杂系统装一个"一键操作"按钮 — 按下 `StartLevel("BossFight")`，加载场景、切换音乐、生成敌人、刷新HUD、播放过场…全部自动完成。这是游戏开发中最常用的模式，你的 GameManager 很可能已经是一个外观！

---

## 🧪 运行方式

将 `FacadePattern.cs` 放入 Unity 项目的任意 `Scripts` 文件夹中，在场景中创建空 GameObject 并挂载 `FacadeDemo` 组件，运行后即可在 Console 中看到所有演示输出。
