## 🎯 今日主题

命令模式将"请求"封装成对象，使你可以用不同的请求、队列或日志来参数化其他对象。在游戏开发中，它是输入处理、撤销重做、回放系统的利器。

---

## 📖 核心知识点

| # | 知识点 | 说明 |
|---|--------|------|
| 1 | ICommand 接口 | Execute() + Undo() — 命令模式的最小契约 |
| 2 | 具体命令 | Move / Jump / Collect — 每种操作封装为一个类 |
| 3 | Undo 关键 | Execute 前保存旧状态，Undo 时恢复 |
| 4 | CommandInvoker | 双栈实现撤销/重做 (undoStack + redoStack) |
| 5 | 回放系统 | 记录命令+时间戳 → 按时间线重播 |
| 6 | 按键绑定 | Dictionary<KeyCode, Func<ICommand>> → 可重绑定 |
| 7 | MacroCommand | 组合多个命令 → 批量执行/撤销 |
| 8 | 幽灵回放 | 竞速游戏中"上一次的自己" |

## 💡 一句话总结

> 把"做一件事"变成"一个对象" — 于是你可以排队、撤销、回放、重绑定，就像操控时间一样。
