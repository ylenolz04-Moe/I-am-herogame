# Day 10 — C# 适配器模式 (Adapter Pattern)

> **日期:** 2026-07-09  
> **难度:** ★★☆☆☆  
> **技术栈:** C# · Unity · 设计模式 · SDK 对接 · 输入系统 · 存档系统

---

## 🎯 今日主题

适配器模式把一个类的接口转换成客户端期望的另一个接口。就像出国用的电源转换插头 — 你的手机需要 USB-C，当地插座是圆孔的，插上转换头就能用。不改旧代码，不破坏新规范，加一层"翻译"就解决问题。

---

## 📖 核心知识点

| # | 知识点 | 说明 |
|---|--------|------|
| 1 | Target / Adaptee / Adapter | 适配器三要素 — 目标接口、被适配者、适配器 |
| 2 | 对象适配器 | 组合方式 — Adapter 持有 Adaptee，C# 首选 |
| 3 | 类适配器 | 继承方式 — C# 不支持多继承，较少使用 |
| 4 | 第三方 SDK 接入 | 成就系统 + 排行榜 → 统一 IGameService |
| 5 | 输入系统迁移 | 旧版 Input Manager → 新版 Input System |
| 6 | 多后端存档 | PlayerPrefs / JSON 文件 / 云存档 → 统一 ISaveSystem |
| 7 | 音频系统适配 | 旧版 LegacyAudio → 新版 IAudioService (含数据格式转换) |
| 8 | 运行时切换后端 | 换一个适配器实例，游戏代码一行不改 |
| 9 | 双向适配 | 新旧代码互相调用 |
| 10 | 外观模式 vs 适配器模式 | 外观简化接口，适配器转换接口 — 不同的意图 |

## 🔗 与其他学习日的关系

- **Day 9 (工厂方法):** 工厂创建对象 → 适配器包装对象，统一对外接口
- **Day 7 (装饰器):** 装饰器增强功能，适配器转换接口 — 都是包装模式但目的不同
- **Day 6 (策略模式):** 策略定义可互换算法 → 适配器让不同接口也能互换
- **Day 5 (命令模式):** 命令封装请求 → 适配器转换请求参数
- **Day 3 (事件系统):** 适配器包装 SDK 后，通过事件系统通知游戏逻辑
- **Day 2 (对象池):** 工厂+池化创建对象 → 适配器统一获取接口

---

## 💡 一句话总结

> 适配器让两个不兼容的接口能一起工作 — 不改旧代码，不破坏新规范，加一层翻译层。对接第三方库、系统迁移时最实用的模式之一。

---

## 🧪 运行方式

将 `AdapterPattern.cs` 放入 Unity 项目的任意 `Scripts` 文件夹中，在场景中创建空 GameObject 并挂载 `AdapterDemo` 组件，运行后即可在 Console 中看到所有演示输出。
