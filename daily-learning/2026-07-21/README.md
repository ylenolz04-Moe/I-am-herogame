---

## 🎯 今日主题

观察者模式 = 微信公众号订阅机制。你关注(Subscribe)了一个公众号(Subject)，它发文时自动推送给你(Notify)。公众号不需要知道你是谁，你也可以随时取关(Unsubscribe)。游戏里的 HP条/成就/音效 都是"关注"了血量变化的粉丝。

---

## 📖 核心知识点

| # | 知识点 | 说明 |
|---|--------|------|
| 1 | 经典手写接口 | `ISubject<T>` + `IObserver<T>` — 手写订阅/取消/通知，理解底层原理 |
| 2 | 血量通知实战 | 一个 Subject(血量) → 5个 Observer(血条/特效/成就/音效/日志) |
| 3 | C# `event` 关键字 | `event Action<T>` — 编译器管理订阅，类型安全，代码最简洁 |
| 4 | `UnityEvent` | Inspector 可视化拖拽绑定，策划/美术友好，可序列化 |
| 5 | EventBus 全局总线 | 系统间完全解耦，发送者和接收者互不认识 |
| 6 | 弱引用观察者 | `WeakReference<T>` — 防止忘记取消订阅导致的内存泄漏 |
| 7 | 三种实现对比 | 手写接口 vs C# event vs UnityEvent vs EventBus — 各有利弊 |

## 💡 一句话总结

> 观察者 = "我有新消息了，关注我的人自己看着办" — 我不需要知道有多少人关注我，也不需要知道他们收到消息后干什么。我只负责：1) 记录谁关注了我 2) 变化时挨个通知。这就是"发布-订阅"的精髓。
